# Bring your own LLM key (BYOK) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the person at the browser (or the operator, through an admin card) save an encrypted
LLM key for one of these providers: Anthropic, OpenAI, Poe, xAI or Gemini. The writer then uses
that key, and so does Grok search for xAI keys. Without one, it falls back to the operator key,
then a local OpenAI-compatible model, then `NullLLM`.

**Architecture:**
- The gateway keeps one `llm` object, a `CallerLLM`.
- `CallerLLM` resolves the right adapter per request from a ContextVar. A pure ASGI middleware sets
  that ContextVar from the `Authorization` / `X-Client-Token` headers.
- Keys are Fernet-encrypted in a new SQLite table. A provider catalogue maps each provider either to
  the existing OpenAI-format client (with explicit URL, key and model) or to a new Anthropic
  adapter.
- New `/api/llm/*` routes and a Settings card manage the keys.

**Tech Stack:** FastAPI, raw sqlite3, httpx, `cryptography` (Fernet), pydantic-settings; React 18 + TS, Storybook.

**Spec:** `docs/superpowers/specs/2026-11-08-byok-design.md`. Read it first. Decision numbers below refer to it.

## Review Focus

1. **A pasted key with surrounding whitespace or a trailing newline** is stripped before testing,
   saving and masking. Test: `test_save_strips_whitespace` (Task 6).
2. **A stored key that no longer decrypts** (`BYOK_ENCRYPTION_KEY` changed) is listed as
   `unreadable: true`. A caller who chose it gets `CallerKeyFailed` ("re-add your key"). It is never
   a 500 and never a fallback. Tests: `test_unreadable_row_listed` (Task 6) and
   `test_unreadable_chosen_key_fails_without_fallback` (Task 4).
3. **Removing the key that is in use** returns the caller to the default chain on the next request.
   Test: `test_delete_active_key_reverts_to_default` (Task 3).
4. **A provider error body that echoes the key** (some vendors quote the bad key back) reaches
   `ProviderError.detail` and the API with the key scrubbed. Test:
   `test_error_detail_scrubs_echoed_key` (Task 2).
5. **The local server stops after startup.** The probe result is cached for 60 s, a failed probe
   makes resolution skip the local model on the next request, and no request blocks longer than the
   probe timeout. Test: `test_local_probe_failure_skips_local` (Task 4).

  - `current_owner() -> str | None`
  - `current_search_key(selector) -> SearchKey | None`
- **Rules:**
  - The selection is computed lazily on first use and memoised in `_CallerState`.
  - With no binding, `CallerLLM` uses `operator_chain()`, with no memo.
  - Adapters are cached in `LLMSelector._adapters`, an `OrderedDict` LRU of 64 entries keyed by
    `(credential_id, updated_at)`.
  - When a `source == "byok"` call raises `ProviderError`:
    1. Wrap it in `CallerKeyFailed(f"Your {label} key failed: {reason}", kind=exc.kind, source="llm", detail=scrubbed)`.
    2. Store it in the state.
    3. Call `emit_live("llm_key", {"provider": id, "model": m, "reason": kind})`.
    4. Raise it.

  - An unreadable chosen row gives a Selection with `source="byok"` whose llm raises
    `CallerKeyFailed("Your saved key can no longer be read. Remove it and add it again in Settings.")`.
    It never falls back.
  - `operator_chain` caches its non-server part per process. A server row change invalidates it
    via `updated_at`.
- **Container:**
  - `llm = CallerLLM(selector)`. `Container` gains `selector: LLMSelector` and `box: SecretBox`.

- **Routes:**
  - `GET /api/llm/providers` returns `{"providers": [{id, label, default_model, key_prefix, supports_search}]}`.
  - `GET /api/llm/keys` returns `{"keys": [KeyView], "status": StatusView}`.
    - `KeyView = {id, provider, label, model, key_tail, active, use_for_search, last_test_ok, last_tested_at, last_error, unreadable}`.
      `unreadable` is true when decrypting the row raises `UnreadableSecret`.
    - `StatusView = {source, provider, model, local: {configured, reachable, model}}`, from
      `selector.for_caller(owner)`, or `operator_chain()` for the server scope.
  - `POST /api/llm/keys/test`, body `KeyIn{provider, api_key, model}`, returns `KeyTestResult` as a
    dict. It is charged with `charge_key_test`.
  - `POST /api/llm/keys`, body `KeyIn + use_for_search: bool = True`.
    - It tests first, charged with `charge_key_test`.
    - If `kind` is `auth`, `model` or `other`, it returns 422 with `{"detail": result.message, "kind": kind}`.
    - If `kind` is `rate_limit` or `network`, it saves with `last_test_ok=False` and returns
      `{"key": KeyView, "warning": message}`.
    - On `ok`, it returns `{"key": KeyView}`.
  - `POST /api/llm/keys/{id}/test` re-tests the stored key and model, records the result and
    returns `{"key": KeyView, "result": ...}`.
  - `PATCH /api/llm/keys/{id}`, body `{model?: str, use_for_search?: bool}`, returns `{"key": KeyView}`.
  - `PUT /api/llm/choice`, body `{key_id: str | None}`, returns `{"status": StatusView}`.
  - `DELETE /api/llm/keys/{id}` returns `{"deleted": true}`.
  - An unknown id, or another owner's id, returns 404 `"No such key."`.
- **Validation (pydantic):**
  - `provider` must be in `PROVIDERS`.
  - `api_key` is stripped and must be 8 to 512 characters, printable ASCII with no spaces after
    stripping.
  - `model` is stripped and must be 1 to 120 characters, falling back to the provider's
    `default_model` when empty.
  - A validation error must not echo `api_key`. Raise `HTTPException(422, "The key must be 8 to 512 printable characters.")`
    from a manual check instead of letting pydantic put the value into `input`.
