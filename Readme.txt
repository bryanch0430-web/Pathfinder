**Pathfinder Local Organized Version**  
Packaging date: 2026-11-16 (Hong Kong time)

This is the version that has been integrated with DeepSeek and can run locally.  
It includes: frontend and backend source code, assets required by the pages, dependency lock files, tests, database snapshot, and handover notes.  
LICENSE and necessary author/third-party asset attributions in the code are retained.  
It does **not** include: Git/GitHub project files, repository promotional materials, search records, old logs, virtual environments, `node_modules`, real API keys, or browser sessions.  
The application’s original third-party login-related code is still present; this package defaults to guest mode and does not require an account.

### 1. Prepare the Runtime Environment
Node.js (version 24 recommended) and Python 3.12+ are required.  
Locally verified environment: macOS, Node.js 24.22.1, Python 3.14.6, pnpm 11.25.0.  
This package contains source code; after extraction you must install dependencies over the network. It is not a portable/no-install program.  
The Windows run method has not been tested.

### 2. Start the Backend (Terminal 1 — enter the extracted `backend` folder)
1. Copy `.env.example` to `.env` (on macOS/Linux use `cp`; on Windows you can use File Explorer).
2. After `DEEPSEEK_API_KEY=` in `.env`, enter your own DeepSeek key.  
   Keep `LLM_PROVIDER=deepseek`. The key must only be placed on the backend and must **not** be put into any frontend `VITE_` variable.
3. `python3 -m venv .venv`  
   (On Windows you can use `py -3 -m venv .venv`.)
4. Activate the environment:  
   macOS/Linux: `source .venv/bin/activate`  
   Windows PowerShell: `.\.venv\Scripts\Activate.ps1`
5. `python -m pip install -r requirements.txt`
6. `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`
7. Health check: http://localhost:8000/api/health  
   It should normally return `healthy`, with the database driver as `sqlite`.

### 3. Start the Frontend (Terminal 2 — enter the `frontend` folder)
1. Copy `.env.example` to `.env`.
2. `npx pnpm@11.25.0 install --frozen-lockfile`
3. `npx pnpm@11.25.0 exec vite --host 127.0.0.1 --port 5174 --strictPort`
4. Open http://localhost:5174/create  
   The homepage http://localhost:5174/ is also accessible; the “Start planning” button on the homepage may guide you toward registration. Going directly to `/create` enters the guest planning page.
5. To stop the service, press `Ctrl+C` in the corresponding terminal.

If ports 8000/5174 are already in use, first identify the process occupying them. Do not terminate unfamiliar processes directly.  
If you change the frontend port, you must also update `CORS_ORIGINS` on the backend. If you change the backend port, you must also update `VITE_API_URL` on the frontend.

### 4. How to Restore Existing Trips
The `backend/pathfinder.db` file included in the package is a consistent snapshot from the time of packaging. It contains 2 travel records (one of which is a 3-day Kyoto itinerary), 8 conversation messages, and budget data.  
Guest identity is stored in the original browser’s `localStorage` and is **not** automatically migrated with the ZIP.  
After switching browsers or devices, a new guest identity is generated by default, and old records may temporarily not appear.  
To restore them, have the receiving agent read the `guest_id` of the target trip from the database, then on the new browser’s localhost:5174 page set (the storage key keeps its original `tripverse_` prefix on purpose, so trips saved before the Pathfinder rename are still found):  
```js
localStorage.setItem('tripverse_guest_id', 'the guest_id of the target trip from the database'); location.reload();
```
Restore only the guest identity corresponding to the target record each time. Do not bulk-reassign ownership of all records.  
If you do not need the old trips, simply create a new trip as normal. There is no need to delete the database.

### 5. Accounts (local, no Supabase)

Supabase is not configured, so the app also ships its own account table: `users` in `backend/pathfinder.db`, scrypt password hashes, and its own HS256 tokens. Guest mode remains the default — you only sign in if you want to.

Create the administrator locally. The password is printed once and is not stored in this repository:

```bash
cd backend
.venv\Scripts\python.exe scripts\create_admin.py --email admin@pathfinder.local
```

The account name is Admin. Sign in with the password the script prints.

Sign in from **Sign in** in the top bar, or open `http://localhost:5174/profile`. Signed-in trips belong to the account instead of a guest UUID, and any trips you planned as a guest are claimed on sign-in.

Change the password (or create another administrator, or promote an existing account) with:

```bash
cd backend
.venv\Scripts\python.exe scripts\create_admin.py --email admin@pathfinder.local --password "a-new-password"
```

Omit `--password` and one is generated and printed once. Ordinary accounts can also be created from the sign-up form. Tokens are signed with `LOCAL_AUTH_SECRET` in `backend/.env`; changing it signs everyone out. Administrator-only routes live under `/api/admin` (for example `GET /api/admin/users`), and the admin flag is only ever granted by the script above — never by sign-up.

### 6. Current Status and Limitations
DeepSeek text generation, streaming output, and tool calling have all been verified against the real API. The web interface successfully generated a full 3-day Kyoto itinerary departing from Shanghai.  
209 backend tests pass; frontend type checking passes.  
The itinerary/interface is still mostly in English; connecting a model does not equal localizing the application.  
Some location positioning and route durations are still estimates; the itinerary will show corresponding notices. Real ticket prices, inventory, or bookings have not been verified.  
Supabase login and cross-device sync have not been configured; local accounts (section 5) cover single-machine sign-in only.  
Independent service keys for Tavily, Google Maps/Routes, ORS, etc. are **not** included in this package. Connecting the model does not mean all data sources have been configured.  
This package contains local travel records. Please keep them according to your own project data retention practices.
